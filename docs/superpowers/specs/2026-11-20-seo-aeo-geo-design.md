# 포트폴리오 6곳 검색 최적화(SEO · AEO · GEO) 설계

- 일자: 2026-11-20
- 결정자: 소유자(변세준). 방향 A 선택, "면접관이 뽑고 싶게 만드는 쪽으로 판단해 진행" 위임
- 대상: 포트폴리오 사이트 `sejunb.com` + 카드에 올라간 프로젝트 중 SEFLIX 를 뺀 5개

## 1. 왜 하는가

순위로 사용자를 모으려는 게 아니다. 면접관이 이름이나 프로젝트를 검색하거나 링크를 열었을 때
"이 사람은 검색 노출을 제대로 아는구나"가 보이게 하는 것이 목적이다.

면접관 입장에서 설득력이 있는 것은 두 가지다.

1. **열어 봤을 때 티 나는 완성도** — 링크를 공유하면 미리보기 카드가 제대로 뜨고, 검색 결과에
   페이지별 제목·설명이 깔끔하게 나오며, 로그인·결제 같은 화면은 검색에 나오지 않는다.
2. **판단이 있는 이야기와 실제 숫자 하나** — 무엇을 왜 노출하고 무엇을 왜 막았는지. 숫자는
   실제 검색 유입이 생길 수 있는 명당재팬의 서치 콘솔 데이터 하나로 보여 준다.

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

**목표**
- 6곳 모두: 페이지별 메타데이터, 정본 주소(canonical), 공유 미리보기(OG · Twitter + 이미지),
  robots, 사이트맵, 도메인에 맞는 구조화 데이터(JSON-LD), AI 검색용 `llms.txt`.
- 비공개 화면(로그인 · 장바구니 · 결제 · 주문 · 마이페이지 · 관리자)은 검색에서 뺀다.
- Vercel 미리보기 배포(프로덕션이 아닌 주소)는 색인되지 않게 한다.
- 근거를 남긴다: 사이트마다 전후 Lighthouse SEO 점수, 구조화 데이터 검증 결과.
- 각 저장소 README 에 "검색 노출" 절을 짧게 둔다(무엇을 노출하고 무엇을 막았는지, 왜).

**하지 않을 것**
- SEFLIX, 그리고 포트폴리오에 없는 저장소(InterestGroup · Junsgram · lea · SHOPPY · new-youtube).
- 본문 내용 새로 쓰기, 검색 순위 보장, 유료 도구.
- 지금 포트폴리오 카드에 "SEO 적용" 같은 줄 넣기. (명당재팬만, 나중에 실제 데이터가 쌓이면 §7)
- 서울, 너와 함께의 언어별 주소(hreflang). 언어를 같은 주소에서 화면 안에서 바꾸는 구조라
  언어별 URL 이 없다. 만들려면 라우팅을 바꿔야 해서 범위 밖.
- 명당재팬 가이드의 FAQ 구조화 데이터. 구글은 2023 년부터 FAQ 리치 결과를 정부·의료 사이트에만
  보여 준다. 효과 없이 마크업만 늘어난다.

**실패로 보는 것**
- 카드에 유행어 목록이 붙는 것. 지어낸 숫자.
- 주문 · 결제 · 관리자 같은 화면이 검색에 잡히는 것.
- 첫 화면이 느려지는 것. JSON-LD 는 서버에서 HTML 에 넣고, 새 클라이언트 JS 는 추가하지 않는다.
  명당재팬은 첫 화면 성능을 공들여 맞춘 사이트라 특히 조심한다.
- 구조화 데이터 검증 오류가 남는 것. 실제 화면에 없는 정보를 구조화 데이터에만 적는 것
  (가격 · 재고 등은 화면에 보이는 값과 같아야 한다).

## 3. 진행 방식 (고려한 것과 선택)

| 안 | 내용 | 장단점 |
|---|---|---|
| **A (선택)** | 6곳 모두 적용. 근거는 README 와 `docs/project-data.md` 에, 카드에는 명당재팬 실제 데이터만 나중에 한 줄 | 실제 데이터라 설득력이 가장 크다. 대신 카드에 보이기까지 몇 주 걸린다 |
| B | 6곳 적용 + 카드마다 "Lighthouse SEO 100 · 구조화 데이터 오류 0" | 바로 보이지만 같은 줄이 6번 반복되고, 데모라 효과를 말할 수 없다 |
| C | 포트폴리오 사이트만 깊게 | 작지만 프로젝트들이 빠진다 |

## 4. 사이트별 설계

공통: 주소는 각 사이트의 운영 주소를 정본으로 쓴다(`metadataBase`). 문구는 사람이 쓴 문체로,
실제 화면 내용과 맞게 쓴다(메모리 `portfolio-docs-voice`).

### 4.1 포트폴리오 — https://sejunb.com (`portfolio`, Next 16 정적 export, 한 페이지)
- 구조화 데이터: `ProfilePage` + `Person`(이름, 직무 "프론트엔드 개발자", `sameAs` 에 GitHub ·
  각 프로젝트 운영 주소) + 프로젝트 6개 목록(`ItemList` → 각 항목 `SoftwareApplication` 또는
  `CreativeWork`, 이름 · 설명 · 주소).
- 사이트맵: 한 페이지라도 만든다(`/` 하나). robots 에 사이트맵을 선언한다. 지금 robots 주석의
  "단일 페이지라 만들지 않았다"는 설명도 함께 고친다.
- **주의:** 지금 robots 가 `/*.txt$` 를 막는다(정적 export 의 RSC `.txt` 중복 색인 방지).
  `llms.txt` 는 `allow: /llms.txt` 로 예외를 둔다. 기존 차단 의도는 유지.
- 제목 · 설명: 이름 검색에 걸리게 "변세준"과 "프론트엔드 개발자"가 제목과 설명 앞쪽에 오게.
- 저장소 규칙: 카드 글자를 바꾸면 빌드 두 번 후 폰트 락파일 커밋(이번엔 카드 글은 안 바꾼다).

### 4.2 명당재팬 — https://lucky.sejunb.com (`lotteryTicket`)
- 이미 있음: 페이지별 메타 · OG · 사이트맵(330 URL) · robots · JSON-LD(Article · Breadcrumb 등) ·
  구글 · 네이버 등록. **새로 만들지 말고 점검과 보강만.**
- 추가: `llms.txt`, robots 의 AI 검색 로봇 허용 명시, 구조화 데이터 검증 기록.
- 서치 콘솔 기준선(§7 비교용, 소유자 캡처):
  - 실적(2026-11-20 확인, 3개월 보기 · 실제 데이터는 주소 이전 직후 11/16~11/18): 클릭 0 · 노출 12 · 평균 게재순위 7.4
  - 페이지 색인 생성(2026-11-23 확인): 색인됨 0 · 색인 안 됨 2(이유 1개)
- 저장소 규칙: `docs/operations.md`, 영어 Conventional Commits, PR.

### 4.3 LUMEN — https://lumen-showroom.vercel.app (`lumen`)
- 공개: `/`, `/products`, `/products/[slug]`, `/room`, `/privacy`.
- 비공개(noindex + robots disallow): `/cart`, `/checkout/**`, `/orders/**`, `/login`.
- 구조화 데이터: 사이트 전체 `WebSite` + `Organization`(가상 쇼핑몰 브랜드), 상품 상세에
  `Product` + `Offer`(가격 KRW · 판매 상태) + `BreadcrumbList`. 값은 `@/catalog/query` 의 상품
  데이터에서 가져와 화면과 같게.
- OG 이미지: 지금 없음. 사이트 대표 이미지 1장 + 상품 상세는 상품 이미지.
- 사이트맵: 공개 페이지 + 상품 전체.

### 4.4 NEXTOUR — https://travel-agency-sooty-mu.vercel.app (`travel`)
- 공개: `/`, `/products`, `/products/[id]`, `/search`, `/compare`.
- 비공개: `/admin/**`, `/mypage`, `/bookings/**`, `/products/[id]/checkout`, `/login/**`, `/reviews/new`.
- 상품 상세: 지금 페이지별 메타데이터가 없다 → 상품명 · 지역 · 요약으로 `generateMetadata`.
- 구조화 데이터: `WebSite`(+ 사이트 검색 `SearchAction` → `/search?q=`), 상품 상세에
  `Product` + 출발일별 가격이 여러 개라 `AggregateOffer`(최저 · 최고가, KRW) + `BreadcrumbList`.
- 사이트맵: 공개 페이지 + 공개 상태(PUBLISHED) 상품만. DB 에서 읽는다.
- 저장소 규칙: 이 저장소는 결정마다 ADR 을 남긴다 → **ADR-0064** 로 "무엇을 노출하고 막는가"를 남긴다.
  CLAUDE.md 의 게이트(typecheck · lint · test · build)와 리뷰 규칙을 따른다. 결제 · 예약 도메인 코드는
  건드리지 않는다.

### 4.5 전국 도로 상황실 — https://traffic-room.vercel.app (`traffic-room/apps/web`)
- 공개: `/`, `/insights`. 둘 다 색인.
- 구조화 데이터: `WebApplication`(무료, 브라우저, 데이터 출처 ITS 공공 데이터 언급).
- **고칠 것:** 지금 설명이 "약 1시간 지연"인데 실제는 20 분 지연이다(2026-11-13 변경). 맞게 고친다.
- OG 이미지: 관제 화면 캡처 1장(README 의 기존 스크린샷 활용 가능).

### 4.6 서울, 너와 함께 — https://date-eight-navy.vercel.app (`날씨데이트/web-ver(이전버전)`, 원격 `byeonsejun/date`)
- 공개: `/`, `/statistics`.
- 구조화 데이터: `WebApplication`(서울 데이트 장소 추천, 지원 언어 ko · en · ja · zh 를 `inLanguage` 로).
- 언어별 주소는 만들지 않는다(§2).

### 4.7 모든 사이트 공통
- **robots:** 기본 허용, 비공개 경로 차단, 사이트맵 선언. AI 검색 로봇(OAI-SearchBot · ChatGPT-User ·
  PerplexityBot · ClaudeBot · Google-Extended · GPTBot)은 막지 않는다(공개 포트폴리오라 노출이 목적).
- **미리보기 배포 막기:** `VERCEL_ENV !== "production"` 이면 전체 noindex. Cloudflare Pages 두 곳
  (포트폴리오 · 명당재팬)은 미리보기 주소에 이미 정본이 운영 주소를 가리키는지 확인만.
- **`llms.txt`:** 사이트가 무엇인지 두세 문장, 주요 페이지 링크, 만든 사람과 포트폴리오 주소,
  기술 스택. 사실만. 프로젝트 쪽 `llms.txt` 는 포트폴리오 `sejunb.com` 을, 포트폴리오 쪽은 각
  프로젝트를 가리켜 서로 이어지게.
- **성능:** JSON-LD 는 서버 렌더 `<script type="application/ld+json">` 으로만. 새 클라이언트 JS 없음.

## 5. 검증 (각 사이트 PR 마다)

- 전후 Lighthouse SEO 점수(모바일, 운영 또는 로컬 빌드 같은 조건).
- 구조화 데이터: schema.org 검증기와 구글 리치 결과 테스트 결과(오류 0).
- `robots.txt` · `sitemap.xml` · `llms.txt` 응답 200, 비공개 경로의 `noindex` 확인.
- 공유 미리보기: OG 태그와 이미지 응답 확인.
- 각 저장소의 기존 테스트 · 게이트 통과. 가능하면 robots · 사이트맵 · noindex 를 확인하는 테스트 추가.
- 결과는 각 저장소 README "검색 노출" 절과 포트폴리오 `docs/project-data.md` 에 기록.

포트폴리오 → 명당재팬 → LUMEN → NEXTOUR → 전국 도로 상황실 → 서울, 너와 함께.

## 7. 나중에 (약 4주 뒤, 2026-12-20 전후)

명당재팬 서치 콘솔 숫자(노출 · 클릭 · 색인된 페이지)를 §4.2 의 기준선과 비교한다. 의미 있는 변화가
있으면 포트폴리오 카드에 한 줄로 싣는다. 변화가 없으면 싣지 않는다.

## 8. 소유자가 할 일

- `sejunb.com` 을 구글 서치 콘솔 · 네이버 서치어드바이저에 등록(이름 검색 노출용). 확인 코드를
  주면 코드에 넣는다.
- 나머지 데모 사이트(vercel.app)는 등록하지 않는다(§1 목적상 불필요).
- 명당재팬 서치 콘솔 기준선: 구현자는 서치 콘솔에 접근할 수 없다. 명당재팬 작업 전에 서치 콘솔
  **실적**(지난 28일 노출 · 클릭)과 **페이지 색인 생성**(색인된 페이지 수) 화면 캡처를 받는다.

## 9. 구현자에게 맡기는 것 (내가 정한 것 포함)

- 메타 문구 실제 문장, OG 이미지 만드는 방법(기존 스크린샷 재사용 우선).
- 구조화 데이터 세부 필드 선택(검증 오류 0 과 "화면에 있는 값만" 원칙 안에서).
- `ItemList` 각 항목을 `SoftwareApplication` 으로 할지 `CreativeWork` 로 할지.
- **내가 정한 것:** AI 로봇을 학습용(GPTBot · Google-Extended)까지 허용, 미리보기 배포 noindex,
  NEXTOUR ADR-0064 작성, 명당재팬 FAQ 마크업 제외, 서울 데이트 hreflang 제외.
